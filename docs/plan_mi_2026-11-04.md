**Answer to the supervisor's question "is MI implemented?": not yet. This plan implements it.**

## 2. The idea in plain words

The witnesses already compare what each sensor *thinks the action is*. MI adds a check on the
sensors' *content*: does this wrist recording belong with this skeleton recording and this video?

We train a small "matcher" that learns which recordings normally go together. For every clip
it then measures how much information each pair of sensors shares (pointwise MI). A swapped-in
recording should share little with the others, even when it looks confident.

This makes the paper's core claim concrete. Over the whole dataset the sensors share a lot of
information (high MI), but the fused model never checks this clip by clip. A single wrong
stream can therefore mislead it while confidence stays high: "high MI is not enough".

## 3. Design

### 3.1 Matcher (InfoNCE critic)
- For each sensor m, an encoder gives a vector e_m, and a projection head h_m maps it to 64 numbers.
- Matching score between sensors m and n: f(e_m, e_n) = h_m(e_m) . h_n(e_n) / tau (tau learned).
- Training: each training clip i is shown with **17 candidate partners**: its own true partner plus
  16 other clips of **the same subject and the same group** (UTD-MHAD: wrist/thigh; MMAct: scene),
  **of any action**. The matcher must pick the true partner (InfoNCE over every ordered sensor pair).
  - **No action labels are used anywhere**, so the matcher is independent of the label-trained witnesses.
  - MMAct: every candidate is time-stretched to clip i's valid length **exactly like the lie donors**
    (same linear resampling; a test checks equality with `operators._resample`), so length can never
    reveal a wrong partner.
  - MMAct: with probability 0.5 the true partner is stretched to a random other length and back, so
    "this signal was stretched" cannot reveal a wrong partner either. Check at Step 4: the same-action swap
    control must not drop like the lies.
- The matcher never sees the fused model, the witnesses' answers, or the validation/test subjects.
- Protocol as `train.py` (AdamW 3e-4, wd 0.05, cosine, bf16, grad clip 1.0, <= 60 epochs, patience 15);
  early stopping on validation InfoNCE loss (fixed validation candidates, seed 12345 + fold).
- **MMAct: 1000 fresh random training clips per epoch** (fixed 4 Nov after a timing run: a full epoch takes
  41 s, so 120 full runs would not fit overnight). UTD-MHAD: all training clips each epoch.

### 3.2 Two versions (main version fixed now, before any result)
| Version | Encoders | Role |
|---|---|---|
| **MI-own (main)** | New sensor encoders, same architecture as the witnesses (`ENCODERS` in `fusion.py`), trained only for matching | Main result |
| MI-frozen (ablation) | Frozen witness encoders (`return_emb`), only the projection heads are trained | Shows whether matching needs its own training |

### 3.3 Dataset-level MI (reported number)
I(X_m; X_n | subject, group) >= log(K+1) - L_InfoNCE, per sensor pair, on validation subjects (K = 16
wrong partners, so the bound cannot exceed log 17 = 2.83 nats; the paper states this).
It is the information two sensors share *beyond who is recording and where*, which is exactly what a lie
from the same person and group breaks.

### 3.4 Pointwise MI per clip (used by the certificate)
i_mn(x) = f(e_m, e_n) - log( (1/K) * sum_j exp f(e_m, e_n^(j)) )

The e_n^(j) are a **fixed reference bank of 64 training clips** of the fold (drawn once with seed
777 + fold, the same for every seed and condition; on MMAct stretched to the judged clip's length).
No test data are reused.

### 3.5 What the certificate gets
- **New signal s4** = - min over sensor pairs of i_mn. It is high when some pair does not belong
  together. It enters the same logistic score (fitted on the validation subject, lambda = 1).
- **New naming candidate:** m* = argmin_m mean_{n != m} i_mn, the sensor that shares least with the
  others (needs M >= 3). It competes with the current odd-one-out rule, and validation picks
  the rule, as before.
- **Link to the existing s2 (exact identity, no number changes):** JS(q_m, q_n) is the MI between
  the predicted label and a fair coin choosing which of the two witnesses is asked (Lin 1991).
  So s2 is label-level MI, and s4 is content-level MI.

### 3.6 Fixed in advance
- The fused model B4 and TMC/ECML are **not changed or retrained**. No MI loss is added to B4,
  because that would break the "no change to the main model" claim.
- The MI design was made after seeing the revision 1 and 2 results, so it is reported as
  **revision 3**, with revisions 1 and 2 kept.
- Main certificate = revision 3 with all four signals and MI-own. Ablation rows: three signals
  (current), MI only, all four with MI-frozen.
- MI results are reported whatever they show, including if MI adds little beyond s2.
