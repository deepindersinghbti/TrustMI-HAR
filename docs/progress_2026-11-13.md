# Progress note, 13 Nov 2026: results frozen, tables by script, reproducibility check, v1 signs on WearGait-PD

Status at the end of 13 Nov: every journal result frozen (fingerprint + git tag), every table and figure built
by one script and checked against the scorers' logs, and the whole scoring re-run from a fresh copy of the
repository with identical results. One planned ablation that had been missed (v1 signs on WearGait-PD) was found,
planned, run, scored and frozen as version 2. Exact settings: `docs/methods_notes.md`, section F.

## 1. Freezing the results (Part C.1 of `docs/plan_followup_2026-11-12.md`)
- **What:** `scripts/freeze_manifest.py` writes a SHA-256 checksum ("fingerprint") of every result file, scorer log,
  config and split file into `results/FROZEN_MANIFEST.sha256`; in check mode it reports any file that changed or
  disappeared. The frozen state is marked with a git tag (`journal-results-frozen`), so the paper can point to it.
- **Rule from here on:** a frozen file never changes. New experiments add new files; the old checksums must stay
  identical, which is checked at every later freeze.

## 2. Every table and figure built by one script (Part C.2)
- **What:** `scripts/make_journal_tables.py` reads only the stored result files and writes the journal tables
  (CSV + LaTeX), the figures and `paper/journal/NUMBERS.md`. While doing so it compares every number it prints with
  the same number in the scorer's own log, and the training accuracies with the training logs, and lists every
  disagreement in `paper/journal/checks.txt`.
- **Problem hit, solved:** the first build reported 117 disagreements, all in the balanced accuracy (macro-F1) of
  the models. The table script averaged the F1 over every class seen in either the answers or the true labels; the
  training code averages over the classes present in the true labels. The table script was changed to the
  training code's definition (`np.unique(y)`). Rebuilt: 0 disagreements. No stored result changed.

## 3. Reproducibility check from a fresh clone (Part C.3)
- **What:** `scripts/check_reproducible.sh` clones the repository into a throwaway folder, checks that the scorer
  code is exactly the code at the tag, copies in the stored model outputs (checked against the fingerprint),
  deletes every file the scorers write, re-runs every scorer and the table script, and compares each re-made file
  with the frozen one (`scripts/compare_outputs.py`: byte-identical or within 1e-12, otherwise FAIL). Log
  differences are listed as notes only (a log is a printout and decides nothing).
- **Problems hit, solved (in order):**
  1. The re-run stopped at the table script: `mi_bound_summary.csv` could not be made, because the MI training
     records (`results/raw/`) were not in the clone. Fixed: the folder is linked into the clone and added to the
     fingerprint.
  2. The script's guard ("code changed since the tag") then stopped on `scripts/freeze_manifest.py`, which had
     changed for fix 1. It is one of the freeze tools, not scorer code, so it was added to the allowed list.
  3. The start line printed the hash of the tag object instead of the commit it points to; display only, fixed.
- **Result:** REPRODUCED. Every re-made table identical; the only log notes are the 10-11 Nov MI logs, which were
  written before WearGait-PD existed and so lack its summary lines.
