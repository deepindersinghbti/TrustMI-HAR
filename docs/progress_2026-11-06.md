Plain-language reading:
- Adding video lifts MMAct from 78.5% to 89.1%. On MMAct, video is the **strongest** single sensor; on UTD-MHAD it is
  the **weakest** (52%). The fused MMAct model may therefore lean on video, so watch/phone lies might hurt it less
  and video lies more. This is the first thing to look at in the lie tests.
- UTD-MHAD B4 is 94.7% with the v2 video features vs 95.0% in the conference paper (expected small shift from the
  preprocessing change, see `docs/data_audit_mmact_video.md` decision 4).
- Both shuffled-label controls sit at chance (about 3%), so there is no leakage.
- MI matchers: validation lower bounds roughly 0.2–2.0 nats per sensor pair, with watch–video and video-related pairs
  usually highest (per-run values in `logs/journal_queue_b.log`).

## 4. Laptop setup (Windows 11, CPU only)

**Code change made on 6 Nov so the scoring scripts run without a GPU** (training scripts untouched):
- new `src/trustmi/device.py`: uses the GPU when present, otherwise the CPU; override with `TRUSTMI_DEVICE=cpu|cuda`;
  bf16 autocast stays on (`TRUSTMI_AUTOCAST=0` turns it off);
- `eval_operators.py`, `cert_evidential.py`, `cert_mi.py`: `.cuda()` → `.to(DEVICE)`, `torch.autocast("cuda", bf16)` →
  `autocast()`. On the desktop GPU the behaviour is identical to before.
- Checked on a CPU-only machine with a random 3-sensor (watch, phone, video) model: loads strictly, CPU bf16 vs fp32
  logits differ by at most 0.015 (the scripts accept up to 0.5), `r_mask` hiding of video leaks exactly 0, and asking
  for `cuda` without a GPU stops with a clear message. Speed there: about 60 clips/s, so a full MMAct lie-test run
  may take a few hours on a laptop CPU. Run it fold by fold (`--folds 0,1`).
- Note for the paper: numbers computed on the CPU can differ from GPU numbers in the last digit (different bf16
  kernels). Every script still checks clean outputs against the stored GPU predictions. Final tables can be re-run on
  the GPU when the desktop is back.

**Setup steps (PowerShell):**
1. `git clone <origin URL> TrustMI-HAR`, then `cd TrustMI-HAR`.

   (`requirements.txt` is a full desktop freeze with CUDA and ROS packages, so it does not install on Windows.)
3. Copy these from the external drive into the clone, keeping the folder structure:
   `runs/` (with weights), `results/raw/`, `results/operators/`, `results/certificate/`, `data/features/`,
   `data/processed/`, `logs/`.
4. Quick check: `python -m pytest tests -q` (any test that needs CUDA will fail on the laptop, and that is expected),
   then a one-fold smoke run once step 1 of section 3 is in place.
